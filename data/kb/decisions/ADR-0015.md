# ADR-0015 — Dual-Plane Physical Database Isolation (Knowledge vs Engagement)

## Context

LLMOps serves two distinct domains with radically different operational and security profiles:
1. **Knowledge Plane**: Global, reusable, non-confidential architectural knowledge (principles, frameworks, controls, patterns, skills, zero-draft templates).
2. **Engagement Plane**: Highly confidential, project-specific client data (stakeholder verbatim, interview statements, maturity boards, trade-off conflicts, and arbitration cards).

Mixing these two domains in a single shared database creates grave confidentiality risks: a flaw in a Cypher query or a misconfigured multi-tenant filter could leak client project data into public demo queries or cross-client sessions.

## Options considered

**Logical multi-tenancy in a single shared database.**
All nodes (Assets, Frameworks, Statements, Conflicts) reside in one database file with an `engagement_id` property. High operational simplicity, but zero defense-in-depth: any unfiltered `MATCH (n) RETURN n` or Cypher injection leaks confidential client engagements.

**Strict dual-plane physical database isolation.**
Physically isolate the Knowledge Base into `data/knowledge.lbug` and each client engagement into dedicated files `data/engagements/<engagement-id>.lbug`. Enforce separate database handles via a connection router (`open_connection`) and strictly prohibit cross-database Cypher joins.

## Decision

Enforce strict dual-plane physical database isolation. The Knowledge Plane is completely decoupled from Engagement databases. Cross-plane Cypher joins are physically impossible at the storage layer. Authorization choke point (`authorise()`) verifies tenant scoping before resolving any engagement file path.

## Consequences

Client confidentiality is guaranteed at the filesystem level. The Knowledge Plane can be mounted and served read-only on public demo instances (`LLMOPS_PLANE=knowledge` or scoped demo) without any possibility of client data exposure. Engagement tools require explicit engagement scope routing.

## Revisit when

A distributed graph database with hardware-enforced cryptographic tenant isolation and verified zero-leakage cross-database federation becomes a core platform dependency.
