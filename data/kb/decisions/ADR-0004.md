# ADR-0004 — Event-driven remediation engine

## Context

Alarms must be mapped to candidate remediation workflows, with deduplication and storm protection, without giving the alerting system a write path to the network.

## Options considered

**Alerting webhooks calling playbooks directly.** Fewest components; no deduplication, no locking, no shadow mode, and the alerting system becomes an actor.

**General-purpose event automation platform.** Very capable, mature; another ecosystem to learn and operate.

**Rulebook engine from the same automation ecosystem as the orchestrator.** Native fit with the orchestration platform, declarative rules, supports a log-only mode.

## Decision

A rulebook engine from the same ecosystem as the orchestration platform maps qualified alarms to workflows, and never executes actions itself: it launches a workflow whose first node is an approval.

## Consequences

One ecosystem, one skill set. Shadow mode is available for rule validation. The mapping layer becomes an asset to version and promote like code.

## Revisit when

Correlation moves into the service management platform, which would make the rulebook engine a pass-through worth reconsidering.
