# ADR-0001 — Git as the source of truth for network and platform configuration

## Context

The engagement needs backup, restore, drift detection and compliance across heterogeneous domains, with evidence usable for accreditation. Configuration state was previously held in tools and in operators' heads.

## Options considered

**Commercial orchestrator with an internal configuration database.** Mature, transactional, vendor-supported; costly, opinionated, and the state lives inside a product.

**Configuration backup tooling only.** Cheap and quick; gives history but no intended state, therefore no real drift or compliance.

**Git as the intended state, with an inventory product alongside.** Reviewable, reproducible, tool-agnostic; requires building the pipeline.

## Decision

Git holds the intended configuration, templates, fallback plans and rules. An inventory product holds assets and per-device data. Nothing reaches a managed system except through the validated pipeline.

## Consequences

Change review becomes mandatory rather than cultural. Rollback is a revert. Undocumented manual changes appear as drift, which is intended. The team must learn a pipeline discipline that did not previously exist.

## Revisit when

A vendor offers an orchestrator whose state can itself be driven from Git without duplication.
