# PAT-006 — Vendor boundary through the northbound interface

## Problem

A vendor element manager owns the configuration of its domain, but the automation chain needs backup, drift detection and recovery actions there.

## Forces

- Bypassing the element manager voids supportability and creates a second master.
- Northbound capability varies by version and licensing and is often overstated.
- The domain still has to be covered by the same governance as the rest.

## Solution

Treat the vendor domain as an appliance with an interface. Backup is an export, drift is a comparison of exports, a fallback plan is a pre-validated delta applied through the interface. Audit the actual interface capabilities before committing scope, using a structured questionnaire, and declare any observability gap rather than discovering it.

## Trade-offs

Automation fidelity is capped by what the vendor exposes. In exchange, supportability is preserved and the configuration has a single master.

## When not to use this

Where the vendor supports and documents direct model-driven access with equivalent guarantees, the indirection adds latency for no benefit.

## Seen in

One mission-critical mobile network engagement (2026), across transport, container platform and vendor-managed core.
